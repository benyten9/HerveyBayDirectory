# Kadence Pro

Rebuild a design as **native Kadence Blocks** the client can still edit. Conversion synthesis is yours; the server validates + persists. You never write raw HTML into `post_content` — you author a tree of real Kadence blocks whose **design is carried in attributes**.

## PART 0 — The one law

> **Design lives in block attributes. Not in CSS. Not in custom classes. Not in `core/html`.**

Every Kadence block is a **dynamic block** (`render_callback`). It renders its wrapper and **compiles a scoped stylesheet from its attributes** at render time — `.kt-adv-heading{uid}`, `.kt-row-layout-id{uid}`, `.kadence-column{uid}`, `.kb-btn{uid}`. Two consequences:

1. **To style anything → set the attribute.** Kadence writes the CSS and the client can still change it in the editor. A custom class + your own CSS breaks editor sync, escalates into `!important`, and is exactly what the client rejects.
2. Because it renders from attributes, authored blocks render correctly on the **front end with no editor save**. (This corrects the old "static-save, open the editor to materialise" claim — that is false for styling. The only thing an editor save adds is generating `source:html` content, icon SVGs, and `<li>` markup — see recovery-save.)

**Never guess an attribute name.** A wrong name is silently ignored → nothing renders → you're tempted to "fix" it with CSS (the #1 failure chain). Use `nibwp/kadence-pro-block-attributes` (reads the live registry) and `references/attribute-reference.md`. The defaults that bite: `htmlTag:'div'`, `currentOverlayTab:'normal'`, `overlayOpacity:30`, `hAlign:'center'`, `lineType:'px'`.

## PART 1 — Where CSS may live (in order)

1. **Block attributes** — first choice for ALL design (typography, color, spacing, background, overlay, min-height, alignment, radius, borders).
2. **`_kad_blocks_custom_css`** post meta — Kadence Blocks Pro's own per-page Custom CSS (it registers + prints it; editable from the page's Kadence panel). Use *only* for what genuinely can't be an attribute: post-loop `.entry-*` internals, third-party form markup, `@keyframes`, `:hover`/pseudo, or boxes targeting `.wp-block-kadence-column`. Persist it with `nibwp/kadence-pro-custom-css`.
3. **Customizer Additional CSS** — site-wide only (`@font-face`, header/footer Element chrome). **Never** page/section styling.

`className` renders on rowlayout, advancedheading, iconlist, core/image — **not** on column, singlebtn, advancedbtn (target those via `.kadence-column{uid}` / `.kb-btn{uid}`).

## PART 2 — Attributes vs content (`source:html`)

Almost everything is a plain JSON attribute — **except** `source:html` fields, which come from the block's saved inner HTML and are never regenerated by render:

| Block | source:html field(s) |
|---|---|
| `advancedheading` | `content` |
| `infobox` | `title`, `contentText`, `number` |
| `listitem` | `text` |

Author these with the text as a `content`/`text` value in the tree node — the converter puts it in the block markup. Everything else (colors, sizes, overlay, icon name, button text, image id) is JSON attributes; don't hand-write its markup.

## Tree node shape

```json
{
  "block": "kadence/rowlayout",
  "attrs": { "htmlTag": "section", "minHeight": 84, "minHeightUnit": "vh",
             "currentOverlayTab": "gradient",
             "overlayGradient": "linear-gradient(to top,rgba(2,2,2,.85),rgba(3,3,3,.7))",
             "overlayOpacity": 100, "bgImg": "https://…/hero.jpg", "bgImgID": 42 },
  "children": [
    { "block": "kadence/column", "children": [
      { "block": "kadence/advancedheading", "content": "Big hero",
        "attrs": { "htmlTag": "heading", "level": 1, "fontSize": [56,40,33], "sizeType": "px",
                   "lineHeight": 1.08, "lineType": "", "color": "#F4F1EB" } },
      { "block": "kadence/advancedbtn", "attrs": { "hAlign": "left" }, "children": [
        { "block": "kadence/singlebtn", "attrs": { "text": "Get started", "link": "/signup" } }
      ]}
    ]}
  ]
}
```

`content` (heading) / `text` (singlebtn is a plain attr, headless-safe) are conveniences; everything else goes in `attrs`. `fontSize` is `[desktop,tablet,mobile]` — **never** `size` (legacy scalar, silently wrong). `lineHeight`/`letterSpacing` are numbers, not arrays. `overlay` is a color string.

## Pipeline (mandatory)

1. `nibwp/skill-preflight { skill_id: "kadence-pro" }` — brand, target mode (page/post/element/pattern), title. Mints `_preflight_token`.
2. `nibwp/load-skill-playbook { skill_id: "kadence-pro" }` → this file + `references/attribute-reference.md`, `references/workflow.md`, `references/troubleshooting.md`.
3. `nibwp/kadence-pro-list-blocks` + `nibwp/kadence-pro-block-attributes { block: "kadence/rowlayout" }` — confirm exact attribute names/types on THIS site before authoring.
4. Build the tree (real blocks; design in attributes; `source:html` content inline). Submit `nibwp/kadence-pro-html-to-blocks { tree, target, dry_run:true, _preflight_token }`. Fix every `failed[]`; heed `warnings[]`.
5. Resubmit `dry_run:false` to persist. Front end renders immediately (dynamic).
6. If the editor shows "Attempt Block Recovery", or you used icons / iconlist / `kadence/image` that need generated markup → run the **recovery-save** (`references/recovery-save.md`). Design is in attributes, so the save preserves it.
7. `nibwp/kadence-pro-feedback { rating }`.

## Section recipe

- **Section** = `kadence/rowlayout` `htmlTag:"section"` (+ `uniqueID`, `padding`, `maxWidth`, `minHeight`). One rowlayout = one row; a 6-card grid = two 3-col rowlayouts stacked.
- **Columns** inside (`columns:N`, `colLayout`). Content blocks inside columns.
- **Dark hero/CTA over image**: `bgImg`+`bgImgID`, `currentOverlayTab:"gradient"`, `overlayGradient`, `overlayOpacity:100`. Never a CSS `::before`.
- **Text** → `advancedheading` (content in markup). **Buttons** → `singlebtn` inside `advancedbtn` (`hAlign`). **Lists** → `iconlist`+`listitem`. **Images** → `kadence/image`, or `core/image` where a static save must survive. **Loops** → `kadence/posts` (fully dynamic). **Client-editable rows** (FAQ/testimonials/pricing) → ACF repeater (`references/acf-editable-content.md`), displayed via a `core/shortcode` block.

## Red flags — stop

- "I'll add a class and style it in CSS" → use the attribute.
- "The attribute didn't work, I'll force it with `!important`" → wrong attribute name; check the registry.
- "I'll do the overlay as a `::before`" → won't paint; `currentOverlayTab:"gradient"`.
- "I'll put this page's CSS in Additional CSS" → site-wide; use `_kad_blocks_custom_css`.
- `core/html` for a card/list/section → use native blocks.
- Hand-writing `<div class="kt-row-layout-overlay">` → its class is read as the block `className` on save and destroys your BEM class.

## Definition of done

Every section a `<section>`; no `core/html` for structure; all design as block attributes; page-only leftovers in `_kad_blocks_custom_css`; nothing page-specific in Additional CSS; heros have a native gradient overlay; loops are `kadence/posts`; client content is an editable ACF repeater; recovery-save → 0 invalid blocks; responsive at 3 breakpoints. Full trap table: `references/troubleshooting.md`.
