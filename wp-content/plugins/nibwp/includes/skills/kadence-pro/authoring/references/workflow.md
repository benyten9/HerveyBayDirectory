# NIBWP Kadence Pro — Build Workflow & Knowledge Base

**Portable doc.** Drop into the `nibwp-skills-pro` repo (e.g. `docs/kadence-workflow.md` or as the body of a `convert-a-design-to-kadence-blocks` skill). Self-contained — no external references required.

Every rule here was earned from a real build (Superbloom, 5 pages) and verified against the live Kadence Blocks Pro block registry. Each "trap" below is a bug that actually shipped.

---

## PART 0 — The one law

> **Design lives in block attributes. Not in CSS. Not in custom classes.**

Every Kadence block is a **dynamic block** (`render_callback`). It renders its wrapper and **compiles a scoped stylesheet from its attributes** at render time:

| Block | Generated selector |
|---|---|
| rowlayout | `.kt-row-layout-id{uid}` (overlay child `.kt-row-layout-overlay`) |
| column | `.kadence-column{uid}` (inner `.kt-inside-inner-col`) |
| advancedheading | `.kt-adv-heading{uid}` |
| singlebtn | `.kb-btn{uid}` (inside `.kb-buttons-wrap`) |
| posts | `.kb-posts-id{uid}` |

**Two consequences:**
1. To style anything → **set the attribute**. Kadence writes the CSS, and the client can still edit it in the editor UI. A custom class + your own CSS breaks editor sync, escalates into `!important`, and is explicitly rejected by the client.
2. Because it renders from attributes, you can mutate attributes in PHP (`parse_blocks` → edit `attrs` → `serialize_block` → `wp_update_post`) and it renders correctly **with no editor save**.

### Never guess an attribute name

A wrong attribute name is **silently ignored** → nothing renders → you get tempted to "fix" it with CSS. That is the #1 failure chain. Verify on the target site:

```php
$bt = WP_Block_Type_Registry::get_instance()->get_registered('kadence/advancedheading');
foreach ($bt->attributes as $k => $a) {
  echo $k.' : '.($a['type'] ?? '?').(isset($a['source']) ? ' /'.$a['source'] : '')
     .' | def='.var_export($a['default'] ?? null, true)."\n";
}
```

## PART 1 — Storage model: where things are allowed to live

### 1. Block attributes — first choice for ALL design
Typography, color, spacing, background, overlay, min-height, alignment, radius, borders.

### 2. `_kad_blocks_custom_css` — page-scoped CSS, **Kadence-native**
A post meta that **Kadence Blocks Pro itself registers and prints** (`kadence-blocks-pro/includes/init.php`: `register_post_meta('_kad_blocks_custom_css')` → output via `get_post_meta(get_the_ID(),'_kad_blocks_custom_css')`). It is Kadence's **per-page Custom CSS** field, editable from the page's Kadence panel. This counts as *inside* Kadence.

Use **only** for what genuinely cannot be an attribute:
- post-loop internals (`.entry-title`, `.entry-summary`, `.entry-meta`, `.post-thumbnail`)
- third-party plugin markup (e.g. SureForms `.srfm-*`)
- `@keyframes` (marquees)
- `:hover` / pseudo-elements
- card boxes that must target `.wp-block-kadence-column` (column doesn't render `className`)

### 3. Customizer Additional CSS — **site-wide only**
`@font-face` declarations and header/footer Kadence **Element** chrome. **Never** page or section styling.

> Priority: **attribute → `_kad_blocks_custom_css` → (never) Additional CSS.**

### className rendering (matters when you must write CSS)
- **Renders `className`:** rowlayout, advancedheading, iconlist, core/image
- **Does NOT:** column, singlebtn, advancedbtn, nav wrapper → target via `.kadence-column{uid}` / `.kb-btn{uid}`, or as children of a classed row (`.my-row .wp-block-kadence-column`)

## PART 2 — Attributes vs content

Almost everything is a plain JSON attribute — **except** fields stored `source:html` / rich-text. Those come from the block's **saved inner HTML** and are never regenerated by render:

| Block | source:html field |
|---|---|
| `advancedheading` | `content` |
| `infobox` | `title`, `contentText`, `number` |
| `listitem` | `text` |

Emit an attribute-only block for these → wrapper + styling render, **text is empty**. This — not "static vs dynamic" — is the only real reason "materialization" ever exists.

```html
<!-- wp:kadence/advancedheading {"uniqueID":"hero1","htmlTag":"heading","level":1,"fontSize":[56,40,33],"sizeType":"px","typography":"Erupha","googleFont":false,"loadGoogleFont":false,"color":"#F4F1EB","lineHeight":1.08,"lineType":"","letterSpacing":0.4,"letterSpacingType":"px"} -->
<h1 class="kt-adv-headinghero1 wp-block-kadence-advancedheading" data-kb-block="kb-adv-headinghero1">Your hero text</h1>
<!-- /wp:kadence/advancedheading -->
```

Everything else (colors, sizes, overlay, icon name, button text, image id) is JSON — **don't hand-write its markup**; let render / the recovery-save produce it.

## PART 3 — Verified attribute reference

### Defaults that bite

| Block | Attribute | Default | Why it matters |
|---|---|---|---|
| rowlayout | `htmlTag` | `'div'` | must set `'section'` |
| rowlayout | `currentOverlayTab` | `'normal'` | **`overlayGradient` is ignored unless `'gradient'`** |
| rowlayout | `overlayOpacity` | `30` | overlay barely visible; set `100` |
| rowlayout | `overlayBlendMode` | `'none'` | keep none/normal |
| rowlayout | `minHeight` | `0` | no height until set |
| rowlayout | `verticalAlignment` | `'top'` | tall hero strands content at top |
| advancedbtn | `hAlign` | `'center'` | why button rows are centered |
| singlebtn | `inheritStyles` | `'fill'` | falls back to global fill color |

### kadence/advancedheading

| Attribute | Type | Default | Notes |
|---|---|---|---|
| `content` | string **/html** | NULL | **source:html** — must be in markup |
| `color` | string | NULL | hex or `palette{n}` |
| `typography` | string | `''` | family name only — **does not load the font** |
| `googleFont` / `loadGoogleFont` | bool | false / true | set both **false** for self-hosted, else Kadence requests fonts.googleapis.com |
| `fontWeight` | string | `''` | `"400"` |
| `fontStyle` | string | `'normal'` | `"italic"` |
| `fontSize` | **array** | `["","",""]` | **[desktop,tablet,mobile]** ← the responsive one |
| `size` | **number** | NULL | ⚠️ legacy scalar — using this instead of `fontSize` is the classic silent failure |
| `sizeType` | string | `'px'` | |
| `lineHeight` | **number** | NULL | **not an array** |
| `mobileLineHeight` | number | NULL | there is **no** `tabletLineHeight` |
| `lineType` | string | `'px'` | ⚠️ use `''` for unitless — leaving `'px'` gives a 1.08**px** line box |
| `letterSpacing` | **number** | NULL | not an array |
| `letterSpacingType` | string | `'px'` | |
| `textTransform` | string | `''` | |
| `htmlTag` | string | `'heading'` | `heading`/`p`/`div`/`span` |
| `level` | number | `2` | h1–h6 |
| `align` | string | NULL | |
| `margin` | **array** | 4 vals | (t,r,b,l) + `marginType` |
| `maxWidth` | **array** | 3 vals | ⚠️ array here, **number** on rowlayout |
| `link` | string | NULL | wraps in `<a>` |

### kadence/rowlayout (a section)

| Attribute | Type | Default | Notes |
|---|---|---|---|
| `htmlTag` | string | `'div'` | → `'section'` |
| `columns` | number | `2` | |
| `bgColor` | string | `''` | |
| `bgImg` / `bgImgID` | string / number | `''` | URL + attachment id |
| `overlay` | **string** | `''` | ⚠️ a **color string** (normal tab only) — not an array/object |
| `currentOverlayTab` | string | `'normal'` | → `'gradient'` |
| `overlayGradient` | string | `''` | full `linear-gradient(...)` |
| `overlayOpacity` | number | `30` | → `100` (bake alpha into stops) |
| `overlayBlendMode` | string | `'none'` | |
| `minHeight` / `minHeightUnit` | number / string | `0` / `'px'` | `'vh'` |
| `minHeightTablet` | number | `''` | exists — don't invent it |
| `maxWidth` | **number** | `''` | ⚠️ number here |
| `padding` / `paddingUnit` | array / string | `["sm","","sm",""]` | supports size keywords |
| `verticalAlignment` | string | `'top'` | `'middle'`/`'bottom'` |

Overlay child `.kt-row-layout-overlay` renders **only** when `has_overlay()` is true, which switches on `currentOverlayTab`.

### Buttons

| Block | Attribute | Type | Default |
|---|---|---|---|
| advancedbtn | `hAlign` / `thAlign` / `mhAlign` | string | `'center'` / `''` / `''` |
| singlebtn | `text` | string | `''` — plain attr, headless-safe |
| singlebtn | `link` | string | `''` |
| singlebtn | `inheritStyles` | string | `'fill'` |

### kadence/posts (query loop)
`columns` / `tabletColumns` / `mobileColumns`, `postsToShow`, `offsetQuery`, `postType`, `image`, `imageRatio`, `excerpt`, `excerptLength`, `date`, `metaCategories`, `aboveCategories`, `loopStyle`. Fully dynamic — **never needs materialising**.

## PART 4 — The workflow

### Step 0 — Preflight (once per site)
1. Import media; record attachment **IDs** (referenced by `bgImgID`, image `id`).
2. Fonts: `@font-face` in Additional CSS (the one legit global use) or a child theme. **`typography:"Erupha"` only emits `font-family` — it does not load the file.**
3. Set the Kadence global **palette** so blocks can reference `palette{n}`.
4. Header/Footer = **Kadence Elements**, not page blocks.
5. Read the design; list sections, each section's bg, and which pieces are cards / lists / loops.

### Step 1 — Build each section
1. **`rowlayout`** with `uniqueID`, `htmlTag:"section"`, `bgColor` or `bgImg`+`bgImgID`, responsive `padding`, `maxWidth`, `minHeight`. (A rowlayout needs a `uniqueID` to emit its wrapper.)
2. **`column`(s)** inside (`columns:N`, `colLayout`). A rowlayout is **one row** — a 6-card 3-col grid = **two** 3-col rowlayouts stacked.
3. Native content blocks inside columns, **styling as attributes**:
   - text → `advancedheading` (content in markup)
   - buttons → `singlebtn` (`text` is an attribute — headless-safe) inside `advancedbtn` (`hAlign`)
   - lists → `iconlist` + `listitem` (item `text` in markup)
   - images → `kadence/image`, or **`core/image`** where a static save must survive
   - icons → `kadence/icon` (`icons:[{icon,size}]`) — SVG generated on editor save
   - loops → `kadence/posts`
4. **Overlay** on hero/CTA over an image: `currentOverlayTab:"gradient"` + `overlayGradient` + `overlayOpacity:100`. Never CSS.
5. Only genuinely-impossible visuals → `_kad_blocks_custom_css`.

**No `core/html` for cards, lists, or sections.** Ever.

### Step 2 — Client-editable content (ACF)
Register the field group on the target page + a repeater with sub-fields. **Critical:** the repeater's `acf-field` post must have `post_parent` = the **field-group post ID** (sub-fields parent to the repeater). If it's `0`, the group renders **empty** in admin — data works, UI doesn't, and it looks hardcoded.

```php
wp_update_post([ 'ID' => $repeaterFieldPostId, 'post_parent' => $groupPostId ]);
acf_get_store('fields')->reset(); acf_get_store('field-groups')->reset(); wp_cache_flush();
$check = acf_get_fields('group_key'); // must list: faqs:repeater subs=2
```

Display via a shortcode that loops `get_field()`, placed as a **`core/shortcode`** block (not `core/html`).

### Step 3 — Canonicalise (authenticated recovery-save)
Clears "Attempt Block Recovery", validates blocks, and generates icon SVGs / iconlist `<li>` / image markup.

**Auth cookie must be signed with a real session token**, or wp-admin bounces to `?reauth=1`:
```php
$token = WP_Session_Tokens::get_instance($uid)->create($exp);
$lg  = wp_generate_auth_cookie($uid,$exp,'logged_in',$token);
$sec = wp_generate_auth_cookie($uid,$exp,'secure_auth',$token);
```
Inject both (`wordpress_logged_in_{COOKIEHASH}`, `wordpress_sec_{COOKIEHASH}`) at path `/` after `clearCookies()`. Then in the editor:
```js
const be = wp.data.select('core/block-editor');
const rebuild = b => wp.blocks.createBlock(b.name, {...b.attributes}, (b.innerBlocks||[]).map(rebuild));
wp.data.dispatch('core/block-editor').resetBlocks(be.getBlocks().map(rebuild));
await wp.data.dispatch('core/editor').savePost();
```
Expect **0 invalid**. If you changed `post_content` via PHP after the editor loaded, **reload first** (stale state).

### Step 4 — Verify
Playwright at desktop / tablet(1024) / mobile(390). No horizontal overflow (`documentElement.scrollWidth ≤ innerWidth`). Heros: overlay present + text readable. Loops: count, crop, meta. **Fix by adjusting attributes first.**

## PART 5 — Trap table (symptom → cause → fix)

| Symptom | Root cause | Fix |
|---|---|---|
| advancedheading renders blank | `content` is source:html; authored attribute-only | put text in the markup |
| Hero not dimmed; no overlay div | `currentOverlayTab` left `'normal'` | set `'gradient'` (+`overlayOpacity:100`) |
| Overlay barely visible | `overlayOpacity` default 30 | set 100 |
| CSS `::before` overlay doesn't paint | pseudo doesn't paint over Kadence's row bg | use overlay attributes |
| Attribute "doesn't work" → reach for `!important` | wrong attribute name (`size` vs `fontSize`) | verify in registry |
| line-height looks broken | `lineType` default `'px'` → 1.08px | `lineType:""` |
| Font not applied | `typography` doesn't load the file | add `@font-face`; set `googleFont/loadGoogleFont:false` |
| Renders `<div>` not `<section>` | `htmlTag` default `'div'` | `htmlTag:"section"` |
| Buttons stuck centered | `advancedbtn hAlign` default `'center'` | `hAlign:"left"` |
| Hero collapses; content under header | `minHeight` unset | `minHeight`+`minHeightUnit:"vh"`, `verticalAlignment` |
| BEM class replaced by `kt-row-layout-overlay …` | hand-written overlay `<div>` → its class parsed as the block `className` on save | never hand-write overlay divs; use attributes |
| `sb-quote--julia` → `sb-quoteu002du002djulia` | editor escapes `-` on round-trip | avoid `--`; repair `str_replace(['u002du002d','u002d'],['--','-'],$c)` |
| `kadence/image` blank after recovery-save | its `save()` can return null | use `core/image` |
| icon/iconlist empty headless | SVG/`<li>` generated client-side on save | run recovery-save |
| `parse_blocks` collapses a section to NULL | column attrs serialised as `[]` | emit `{}` (`empty($a)?'{}':wp_json_encode($a)`) |
| ACF group empty in admin | repeater `post_parent = 0` | reparent + reset caches |
| `?reauth=1` loop | cookie lacks a real session token | `WP_Session_Tokens::create` |
| Page CSS vanished after save | stored where Kadence regenerates | `_kad_blocks_custom_css` |
| Frontend stale after attribute write | Kadence caches generated CSS | `wp_update_post` bumps `post_modified`; verify visually |
| Image `srcset` 404s | missing intermediate sizes | `wp_generate_attachment_metadata` |
| `html-to-blocks` duplicated the page | target `update` **appends** | delete old top-level blocks after |
| `_preflight_token` rejected | single-use per persist | re-run `nibwp/skill-preflight` |

**Diagnostic order:** real attribute name? → responsive variant? → is a default overriding? → is it `source:html`? → only then `_kad_blocks_custom_css`.

## PART 6 — Red flags (stop immediately)

- "I'll add a class and style it in CSS" → **use the attribute**
- "The attribute didn't work, I'll force it with `!important`" → **wrong attribute name**
- "I'll do the overlay as a `::before`" → **won't paint**; use `currentOverlayTab:"gradient"`
- "I'll put this page's CSS in Additional CSS" → **that's site-wide**; use `_kad_blocks_custom_css`
- Hand-writing `<div class="kt-row-layout-overlay">` → **destroys the block className on save**
- `core/html` for a card/list/section → **use native blocks**
- Hardcoding FAQ/testimonial rows → **ACF repeater**

## PART 7 — Definition of Done (per page)

- [ ] Every section is a `<section>` (`rowlayout htmlTag:"section"`)
- [ ] No `core/html` for cards / lists / sections
- [ ] All typography, color, spacing, overlay, bg, min-height, alignment set as **block attributes**
- [ ] **Nothing** page-specific in Customizer Additional CSS (only `@font-face` + header/footer Element chrome)
- [ ] Page-only leftovers live in `_kad_blocks_custom_css`
- [ ] Hero/CTA over image: native gradient overlay, text readable
- [ ] Loops are `kadence/posts`; client content is an ACF repeater editable on the edit screen (`acf_get_fields()` verified)
- [ ] Recovery-save: **0 invalid blocks**, no recovery prompt
- [ ] Responsive verified at 3 breakpoints; matches the design
- [ ] Client can open any block in the editor and change its design **without touching code**
