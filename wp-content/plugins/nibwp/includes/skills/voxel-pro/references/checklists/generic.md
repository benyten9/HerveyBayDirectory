# Checklist — any Voxel template

- [ ] `nibwp/voxel-info` read first. Post type keys, taxonomy keys and which
      modules are switched on are per site.
- [ ] Widget names confirmed against `nibwp/voxel-pro-catalog`, not memory.
- [ ] Field and filter keys read from the catalog for the post type in hand.
- [ ] Dynamic tags used wherever the content belongs to a listing. Hard-coded
      text in a template that renders per listing is always a mistake.
- [ ] Design decisions taken from `nibwp/design-direction` rather than
      invented — colors, spacing, type.
- [ ] Responsive values set for tablet and mobile on anything with columns.
- [ ] A dry run passed with no `failed[]` items, and the warnings read rather
      than skimmed. An empty-rendering tag is usually either an optional field
      or a key that is subtly wrong, and only you know which.
- [ ] The assignment decided deliberately: replacing an existing template
      changes what visitors see immediately.
- [ ] The user told what was written, where it was assigned, and what it
      replaced.
